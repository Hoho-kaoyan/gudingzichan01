# 第一部分：系统概述

## 1.1 项目简介

固定资产管理系统（Fixed Asset Management System）是一个基于 Web 的企业级资产管理系统，旨在帮助企业或组织高效管理固定资产的全生命周期，包括资产的登记、分配、交接、退回、审批及安全检查联动等全部环节。

## 1.2 系统目标

1. **提高资产管理效率**：通过数字化管理，减少人工操作，提高资产管理的准确性和效率。
2. **规范资产流转流程**：建立标准化的资产交接、退回、调拨审批流程，确保资产流转的可追溯性。
3. **实现多级权限管理**：区分管理员、组长、普通用户权限，确保系统安全。
4. **完整记录资产历史**：记录资产所有操作历史，支持审计和追溯。
5. **安全检查联动**：将安全检查任务与资产变动自动关联，确保资产安全检查落地。
6. **支持批量操作**：支持 Excel 批量导入用户和资产，提高数据录入效率。

## 1.3 技术架构

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 后端框架 | Python FastAPI + SQLAlchemy | 高性能 Web 框架 + ORM |
| 前端框架 | React 18 + Ant Design 5 + Vite | 现代 UI 框架与构建工具 |
| 数据库 | SQLite（可升级 Oracle/SQL Server） | 轻量级数据库，支持内网部署 |
| 认证方式 | JWT Token | 无状态身份认证 |
| Excel 处理 | Pandas + OpenPyXL | 批量导入导出 |

## 1.4 系统部署

- **前端**：`http://localhost:3000`（开发环境）
- **后端 API**：`http://localhost:8000`（开发环境）
- **API 文档**：`http://localhost:8000/docs`（Swagger UI）

## 1.5 术语表

| 术语 | 说明 |
|------|------|
| EHR号 | 员工健康记录号，7位数字，用户唯一标识 |
| 资产编号 | 资产的唯一标识符 |
| 资产大类 | 资产的分类，如"办公用品"、"电子设备配件" |
| 实物名称 | 资产的具体名称，如"终端"、"显示器"、"主机" |

| 离职联动 | 标记用户离职时，自动为该用户全部资产生成安全检查任务 |

# 第二部分：角色与权限

## 2.1 角色定义

系统支持三种用户角色：**管理员（admin）**、**组长（leader）**、**普通用户（user）**。

### 2.1.1 管理员（admin）

拥有系统最高权限，负责系统日常管理和维护。

| 职责 | 说明 |
|------|------|
| 用户管理 | 创建、编辑、删除、批量导入用户 |
| 资产管理 | 创建、编辑、删除、批量导入资产；可直接更新资产 |
| 审批管理 | 审批交接、退回、编辑申请 |
| 安全检查 | 发布检查任务、管理检查类型、配置联动规则 |
| 统计看板 | 查看系统全部统计数据 |

### 2.1.2 组长（leader）

管理本组资产，在特定范围内拥有调拨权限。

| 职责 | 说明 |
|------|------|
| 本组资产管理 | 查看本组全部资产 |
| 组内调拨 | 修改本组资产使用人（仅限本组用户）；交接自己名下资产时可转给任意用户 |
| 提交申请 | 提交本组资产的退回申请 |
| 安全检查 | 接收并执行分配给自己的检查任务 |

### 2.1.3 普通用户（user）

使用自己名下资产，提交流转申请。

| 职责 | 说明 |
|------|------|
| 资产使用 | 查看自己使用的资产 |
| 申请交接 | 发起自己名下资产的交接申请 |
| 申请退回 | 发起自己名下资产的退回申请 |
| 提交编辑 | 提交自己名下资产的编辑申请（需审批） |
| 安全检查 | 执行分配给自己的安全检查任务 |

# 第三部分：功能模块说明

## 3.1 登录与认证

### 3.1.1 EHR号验证

用户输入7位数字EHR号后，系统实时验证该EHR号是否存在。验证成功显示对应用户姓名，验证失败提示"EHR号不存在"。此机制确保登录前已确认用户身份。

### 3.1.2 登录

用户输入EHR号和密码后提交登录请求。后端验证通过后返回JWT Token，客户端将Token存入localStorage，后续所有API请求自动携带该Token。Token有效期30天，过期后需重新登录。

**默认管理员账户**：EHR号 `0000001`，密码 `Aa@1234567`（init_db.py初始化创建）

**安全策略**：
- 用户首次登录时必须修改密码
- 新密码必须满足强口令要求：8位以上，包含大写字母、小写字母、数字、特殊字符(@#$%^&)

### 3.1.3 前端路由守卫

用户未登录时访问任何页面，自动跳转至登录页。Token失效（401响应）时，自动登出并跳转登录页。

## 3.2 首页统计看板

首页以卡片形式展示四类统计数据：

| 统计项 | 说明 |
|--------|------|
| 资产总数 | 系统全部未删除资产数量 |
| 在用资产 | 状态为"在用"的资产数量 |
| 用户总数 | 系统全部未删除用户数量 |
| 待审批 | 当前所有待审批申请数量（交接待确认+待审批、退回待审批、编辑待审批之和） |

统计数据实时从后端 `/api/stats/` 接口获取。

## 3.3 用户管理

管理员可管理所有用户信息，普通用户无法访问此模块。

### 3.3.1 用户列表

表格展示所有用户，包含字段：**EHR号、姓名、组别、角色、状态**。支持按角色（管理员/组长/普通用户）、状态（在岗/离职/长期出差/借调/产假）筛选，支持按EHR号或姓名关键字搜索。

### 3.3.2 新增用户

管理员点击"新增用户"按钮，填写EHR号（7位数字，唯一）、姓名、组别、角色、状态、密码后提交。EHR号重复或格式错误时返回明确提示。

### 3.3.3 编辑用户

管理员可修改用户的姓名、组别、角色、状态、密码。EHR号作为唯一标识不可修改。

### 3.3.4 删除用户（软删除）

用户删除不做物理删除，仅标记 `deleted_at` 和 `deleted_by_id`。删除后该用户无法登录，但在资产历史记录中仍保留操作人信息。

### 3.3.5 标记离职

管理员可对在职用户执行"标记离职"操作。操作将触发以下流程：

1. 用户状态更新为"离职"
2. 自动为该用户全部资产生成安全检查任务（source=resignation）
3. 任务分配给该用户，完成后允许提交退回/交接申请

### 3.3.6 批量导入用户

管理员上传符合格式的Excel文件批量导入用户。格式要求：EHR号（7位数字）、姓名、组别、角色（默认user）、密码（默认Aa@1234567）。EHR号重复时跳过该行。导入的用户首次登录时必须修改密码。

## 3.4 资产管理

### 3.4.1 资产列表

展示资产全部字段，支持多条件筛选：资产编号关键字、所属大类、状态（在用/在库）、可用状态（可用/维修中/已报废）、使用人、组别等。管理员可见全部资产，组长可见本组资产，普通用户仅见自己名下资产。

**列表主要字段**：资产编号、所属大类、实物名称、规格型号、状态、可用状态、使用人、存放地点等。

### 3.4.2 新增资产

管理员或普通用户均可新增资产。管理员新增时可指定使用人；普通用户新增时使用人默认为自己。新增资产时若"在用"则必填使用人，"在库"则使用人为空。

**实物情况（必填）**：资产编号（唯一）、所属大类、实物名称。

**实物情况（可选）**：规格型号、状态（默认在用）、MAC地址、IP地址。

**盘点情况（可选）**：存放办公地点、存放楼层、座位号、使用人、使用人组别、备注说明。

**扩展字段（可选）**：件数、所在团队、购置日期、卡片编号、检查执行人、电脑类型/应用/计算机名、显示器1/2型号及序列号、资产管理联系人、预留1～6。

### 3.4.3 编辑资产

**管理员**：可编辑资产全部字段（资产编号除外），修改立即生效，无需审批。修改使用人时触发调拨联动（见4.4节）。

**普通用户**：仅可编辑自己名下资产的以下字段——实物名称、规格型号、MAC地址、IP地址、存放办公地点、存放楼层、座位号、备注说明；不能修改使用人和状态。编辑操作需提交申请，待管理员审批通过后生效。

### 3.4.4 删除资产（软删除）

管理员删除资产不做物理删除，仅标记 `deleted_at` 和 `deleted_by_id`。删除后资产从列表消失，但历史记录中仍保留。

### 3.4.5 批量导入资产

管理员上传Excel文件批量导入资产。系统对每行数据按资产编号查重——编号存在且未删除则跳过，编号存在且已删除则恢复并更新该记录，编号不存在则新增。

**必填列**：资产编号、所属大类、实物名称。

**可选列**：规格型号、状态（在用/在库）、MAC地址、IP地址、存放办公地点、存放楼层、座位号、使用人EHR号、使用人组别、备注说明、件数、所在团队、购置日期、卡片编号、检查执行人ID、电脑类型/应用/计算机名、显示器1/2型号及序列号、资产管理联系人、预留字段。

**列名兼容**：系统兼容多种列名写法，例如"状态"/"实物状态"、"IP地址"/"终端IP号"、"MAC地址"/"终端mac地址"、"存放楼层"/"具体存放楼层"均可。

**入库联动**：成功导入且带使用人的资产，自动按联动配置（默认检查类型或实物名称→检查类型映射）下发安全检查任务，任务分配给该使用人。

### 3.4.6 导出资产 Excel

管理员可将当前筛选结果导出为Excel文件，文件格式与导入格式一致，便于数据备份和上报。

### 3.4.7 查看资产历史

每条资产记录可查看完整的流转历史，包括：创建、编辑、交接、退回、审批等操作。历史记录按时间倒序展示，包含操作类型、操作人、操作时间、变更详情。

## 3.5 资产交接

### 3.5.1 发起交接申请

用户（管理员可代任何人）选择资产和转入人后提交交接申请。交接仅限**在用资产**。

**交接权限规则**：

- **普通用户**：只能交接自己名下的在用资产，转入人可为任意用户（含管理员）。
- **组长**：交接**自己名下**资产时与普通用户一致（转入人可为任意用户）；交接**组内他人**资产时，转入人仅能为本组用户。
- **管理员**：可代任何人发起，转入人可为任意用户。

**交接联动**：创建交接申请时，系统校验转出人是否有该资产的未完成安全检查任务。若有，则拒绝创建申请，提示"请先完成数据安全检查"；若无，则自动下发安全检查任务（source=transfer）给转出人，并将交接单状态置为"待完成联动安全检查"。

### 3.5.2 转入人确认

交接申请提交后，转入人在资产交接页面查看待确认申请，可选择确认或拒绝：

- **确认**：申请状态变为"待审批"，进入管理员审批环节。
- **拒绝**：申请状态变为"确认拒绝"，流程结束。

### 3.5.3 管理员审批

管理员在审批管理页面查看所有待审批交接申请，可批准或拒绝：

- **批准**：资产使用人更新为转入人，申请人可到资产交接页面查看结果。
- **拒绝**：申请状态更新为"已拒绝"，资产信息不变。

### 3.5.4 撤回申请

申请人在转入人确认前可撤回自己的交接申请。若该申请关联了联动安全检查任务，撤回时同时取消该任务。

### 3.5.5 交接状态说明

| 状态 | 说明 |
|------|------|
| 待确认 | 等待转入人确认 |
| 待完成联动安全检查 | 已下发联动安检任务，等待转出人完成 |
| 待审批 | 转入人已确认，等待管理员审批 |
| 已批准 | 管理员已批准，资产已转移 |
| 已拒绝 | 管理员已拒绝 |
| 确认拒绝 | 转入人已拒绝 |

## 3.6 资产退回

### 3.6.1 发起退回申请

用户选择自己名下在用资产，填写退回原因（可选）后提交申请。退回时还可修改资产的MAC地址、IP地址、存放地点、座位号等信息，或指定新的保管人。

退回仅限**在用资产**。

### 3.6.2 管理员审批

管理员审批退回申请时可批准或拒绝：

- **批准**：资产使用人清空（或更新为新保管人），资产状态变为"在库"，未完成的安全检查任务标记为"已退库"。
- **拒绝**：申请状态更新为"已拒绝"，资产信息不变。

## 3.7 资产编辑申请

普通用户修改自己名下资产信息时，不能直接修改（管理员可直接修改），而需提交编辑申请。

### 3.7.1 可编辑字段

实物名称、规格型号、MAC地址、IP地址、存放办公地点、存放楼层、座位号、备注说明。**使用人和状态不可通过此方式修改**（需通过交接或退回流程）。

### 3.7.2 审批流程

管理员审批通过后，资产信息按申请内容更新；拒绝则资产不变。同一资产同一时间只能有一条待审批的编辑申请。

## 3.8 审批管理

管理员在审批管理页面集中处理所有待审批申请。页面分三个标签页：**交接申请、退回申请、编辑申请**。

每个标签页展示申请列表，支持按关键字搜索。管理员可查看申请详情，填写审批意见后批准或拒绝。

同时提供**已审批**标签页，记录所有历史审批操作，包含审批结果、审批时间、审批人、审批意见。

## 3.9 安全检查任务

### 3.9.1 检查类型管理

管理员可管理安全检查类型，包括新增、编辑、删除（软删除/停用）检查类型。每个检查类型包含多个**检查项**，每项支持标记为"必填"或"可选"，并可配置检查项名称（如"电源线是否完好"）。

### 3.9.2 发布任务

管理员发布安全检查任务时：

1. 选择检查类型。
2. 选择资产（支持多选，支持按资产编号/名称/使用人/执行人等多字段搜索）。
3. 填写任务标题、描述、截止时间（可选）。

系统自动为每个资产的使用人创建任务资产关联记录（source=manual）。若资产设定了检查执行人（safety_check_executor_id），任务分配给执行人；否则分配给使用人。资产无使用人时跳过该资产。

### 3.9.3 任务列表

管理员可查看全部安全检查任务，支持按**状态**（进行中/已完成/已逾期/已取消）和**来源**（手动发布/入库联动/交接联动/调拨联动/离职联动）筛选。

任务详情展示任务的全部资产清单，包含每项资产的分配用户、检查状态（待检查/已检查/已退库/已逾期）和检查结果。

### 3.9.4 执行检查

普通用户（及管理员）登录后，可在"我的检查任务"页面查看分配给自己的任务。

- **待检查**：尚未完成检查的任务，点击"开始检查"可对每个检查项选择"是"或"否"，填写备注后提交。
- **已逾期**：截止时间已过但仍未完成的任务，支持补检。
- **已完成**：已提交结果的任务，不可修改。

任务中所有资产均完成检查后，任务状态自动更新为"已完成"。

### 3.9.5 检查结果

每项检查记录整体结果（是/否）和各检查项结果（是/否），并可填写备注。若整体结果为"否"，说明该资产有不合格项，需要关注。

### 3.9.6 过期任务

截止时间已过且仍为"pending"状态的任务资产，在列表加载时自动更新为"overdue"状态。管理员可在"已逾期"标签下查看和处理。

## 3.10 联动安全检查配置

管理员可在"安全检查任务管理"页面点击"联动任务配置"配置系统自动分配任务的规则。

### 3.10.1 全局默认检查类型

当某资产的实物名称未配置映射时，系统使用此默认检查类型创建任务。管理员可从已启用检查类型中选择或清空。

### 3.10.2 实物名称→检查类型映射

管理员可新增"实物名称→检查类型"映射，为特定实物名称（如"终端"）指定对应的检查类型。映射按实物名称唯一，已配置的映射可编辑或删除。

**分配规则**：入库/交接/调拨/离职时，系统先按资产实物名称查映射表，若有映射则用对应检查类型；无映射则用全局默认检查类型；均无配置则不创建任务。

## 3.11 联动安全检查机制

系统将安全检查任务与资产变动自动关联，共有五种联动场景：

| 场景 | 触发时机 | 任务分配给 | 任务来源标识 |
|------|----------|-----------|-------------|
| 入库联动 | 单个新增或批量导入资产且有使用人 | 使用人 | inbound |
| 交接联动 | 创建交接申请（转出人尚未完成该资产安检） | 转出人 | transfer |
| 调拨联动 | 管理员/组长修改资产使用人 | 原使用人或新使用人（视情况） | reallocation |
| 离职联动 | 标记用户离职 | 离职用户 | resignation |
| 手动发布 | 管理员手动发布任务 | 使用人或执行人 | manual |

**调拨联动说明**：修改使用人时不直接更新 `user_id`，而是为相关用户创建安全检查任务，并将"待生效调拨"记录入库。相关用户完成检查后，系统自动将 `user_id` 更新为新使用人。

**交接联动说明**：转出人完成安全检查后，交接申请才允许进入审批环节；若转出人拒绝或超时，联动任务取消。

# 第四部分：业务流程

## 4.1 资产入库流程

```
[管理员新增资产 或 批量导入]
          │
          ▼
    资产写入数据库
          │
          ├─── 有使用人 ──→ 按联动配置创建安全检查任务（source=inbound）
          │                  分配给：safety_check_executor_id > user_id
          │
          └─── 无使用人（直接入库）──→ 不创建任务
```

**入库联动条件**：资产有使用人（user_id 非空）且联动配置存在（全局默认类型或实物名称映射）。

## 4.2 资产交接流程

```
[用户/管理员发起交接申请]
          │
          ▼
    系统校验：转出人是否有该资产未完成安检？
          │
    ┌─────┴─────┐
    │ 有未完成任务  │ 无未完成任务
    ▼             ▼
  拒绝创建      为转出人创建安全检查任务
  提示用户      （source=transfer）
                 │
                 ▼
          交接单状态：待完成联动安全检查
                 │
                 ▼
        [转出人执行安全检查]
                 │
                 ▼
          任务完成，状态变更为"已完成"
                 │
                 ▼
          交接单状态：待审批（转入人确认后）
                 │
                 ▼
        [转入人确认/拒绝]
                 │
          ┌──────┴──────┐
          ▼             ▼
       确认          拒绝
          │             │
          ▼             ▼
    管理员审批      申请结束
          │
    ┌─────┴─────┐
    │ 批准      │ 拒绝
    ▼           ▼
  资产转移给    申请结束
  转入人
```

## 4.3 资产退回流程

```
[用户发起退回申请]
          │
          ▼
    填写退回原因（可选）
    可同时修改资产信息（MAC/IP/地点等）
          │
          ▼
    提交申请
          │
          ▼
    管理员审批
          │
    ┌─────┴─────┐
    │ 批准      │ 拒绝
    ▼           ▼
  使用人清空    申请结束
  状态改为"在库"
  未完成任务标"已退库"
```

## 4.4 调拨联动流程（修改使用人）

```
[管理员/组长修改资产使用人]
          │
    ┌─────┴─────┐
    │ 有原使用人  │ 无原使用人（在库）
    ▼             ▼
 为原使用人A    为新使用人B
 创建安检任务   创建安检任务
 写入待生效调拨  写入待生效调拨
          │
          ▼
    资产 user_id 暂不更新
          │
          ▼
    [A/B 执行安全检查]
          │
          ▼
      任务完成
          │
          ▼
    自动更新 user_id 为新使用人
    删除待生效调拨记录
```

## 4.5 离职联动流程

```
[管理员标记用户离职]
          │
          ▼
    提示"是否完成数据安全检查进行资产交接？"
          │
          ▼
    为该用户全部资产生成安全检查任务
    （按实物名称查联动配置确定检查类型）
          │
          ▼
    任务分配给该离职用户
          │
          ▼
    用户完成全部任务后
          │
          ▼
    允许提交退回/交接申请
```

## 4.6 安全检查执行流程

```
[用户查看"我的检查任务"]
          │
          ▼
    选择"待检查"或"已逾期"Tab
          │
          ▼
    点击"开始检查"
          │
          ▼
    对每个检查项选择"是"/"否"
    填写备注（可选）
          │
          ▼
    提交检查结果
          │
          ▼
    系统更新任务进度
    若全部资产均完成 → 任务状态变为"已完成"
```

## 附录B：常见问题解答

### B.1 登录问题

**无法登录**：确认EHR号和密码正确，默认管理员EHR号`0000001`，密码`Aa@1234567`。确认后端服务已启动。

**首次登录必须修改密码**：如果登录后弹出"首次登录必须修改密码"弹窗，请按照强口令要求设置新密码（8位以上，包含大写字母、小写字母、数字、特殊字符）。

**EHR号验证不通过**：检查EHR号是否为7位数字，确认用户在系统中存在（未被删除）。

### B.2 资产管理问题

**无法选择使用人**：检查目标用户是否已创建且未被标记离职。管理员可为任意用户，普通用户不能给自己分配资产。

**交接申请被拒绝**：系统要求转出人先完成该资产的联动安全检查任务，完成后再次尝试交接。

**批量导入失败**：检查Excel格式，确认列名与系统要求一致（参考附录A）。查看导入结果中的错误详情定位具体问题。

### B.3 安全检查问题

**任务未分配给自己**：确认资产的使用人或检查执行人设置正确。任务按`safety_check_executor_id`优先分配，其次按`user_id`分配。

**修改使用人后任务未更新**：调拨联动需相关人员完成安全检查后才生效使用人更新，在此之前资产仍归属原使用人。

### B.4 数据库问题

**数据库损坏**：删除`backend/assets.db`后重新运行`python init_db.py`初始化新数据库（会丢失所有数据）。

**迁移后无法连接**：确认`.env`文件中数据库连接信息（主机、端口、用户名、密码）正确，数据库服务已启动。
