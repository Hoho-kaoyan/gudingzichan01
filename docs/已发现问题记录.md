## 问题一：资产管理模块前端只返回 100 条数据

### 现象

资产管理页面（资产列表）最多只显示 100 条资产，但数据库中实际数量远大于 100。后端数据完整，不是导入丢失。

### 根因

**后端资产列表接口的 `limit` 默认值就是 100**：

```266:268:backend/routers/assets.py
@router.get("/", response_model=List[AssetResponse])
async def get_assets(
    skip: int = 0,
    limit: int = 100,
```

**前端请求时没有传 `limit`**，于是命中默认值 100：

```84:89:frontend/src/pages/AssetManagement.jsx
  const fetchAssets = async (extraFilters) => {
    setLoading(true)
    try {
      const params = { ...filters, ...(extraFilters || {}) }
      const response = await api.get('/assets/', { params })
      setAssets(response.data)
```

对比项目内其他页面，都显式传了大 `limit`，所以只有资产管理这一处受影响：

| 页面 | 位置 | 传参 |
|---|---|---|
| `UserManagement.jsx` | 第 196 行 | `limit: 10000` |
| `SafetyCheckTaskManagement.jsx` | 第 190 行 | `limit: 1000` |
| `TransferManagement.jsx` | 第 93 行 | `limit: 10000` |
| **`AssetManagement.jsx`** | **第 88 行** | **未传，落到默认 100** |

### 补充说明

该限制**只影响列表展示，不影响 Excel 批量导入**。导入接口 `assets.py` 第 935 行是 `for index, row in df.iterrows()` 全量遍历，没有行数上限；导入结果里写的"成功 N 条"是准确值。（另有 `max_errors = 100` / `max_conflicts = 100`，那只是返回给前端弹窗展示的错误/冲突明细条数上限，不是导入条数限制。）

### 修复方案

**方案 A（短期，改动最小）**：前端 `fetchAssets` 请求时带上大 limit

```jsx
// frontend/src/pages/AssetManagement.jsx 第 87 行
- const params = { ...filters, ...(extraFilters || {}) }
+ const params = { ...filters, ...(extraFilters || {}), limit: 10000 }
```

**方案 B（长期，推荐）**：做真正的服务端分页

- 后端返回 `total` 计数（或新增 `X-Total-Count` 响应头）
- 前端 `<Table>` 启用受控分页（`pagination={{ current, pageSize, total, onChange }}`），翻页时传 `skip`/`limit`
- 理由：资产量上千后，一次性拉全量会明显拖慢首屏，且导出/筛选逻辑也依赖同一接口

**折中建议**：先上方案 A 止血，资产规模超过 1000 条后再做方案 B。

## 问题二：EHR 号第一位为 0 的用户无法导入，连带其资产也无法导入

### 现象

1. **用户管理 → 批量导入用户**：EHR 号以 0 开头（如 `0000001`）的用户导入失败，报错 `EHR号格式错误（必须为7位数字）`。
2. **资产管理 → 批量导入资产**：属于这类用户的资产导入失败，报错 `使用人EHR号1不存在`（注意报错里的号码前导零已丢失，变成了 `1`）。

### 根因

Excel 单元格是**数值格式**时，pandas 会把 `0000001` 读成整数 `1`。`pd.read_excel` 没有指定 `dtype`，导致前导零在读取阶段就丢失，之后再怎么转字符串都补不回来。

**用户导入侧**

```669:669:backend/routers/users.py
        df = pd.read_excel(io.BytesIO(contents))
```

```694:694:backend/routers/users.py
                ehr_number = cell_to_str(row.get('EHR号', ''))
```

`cell_to_str` 只负责把浮点 `1.0` 还原成 `"1"`，无法恢复前导零（`backend/excel_io.py` 第 10-28 行）：

```22:27:backend/excel_io.py
    try:
        f = float(s)
        if f == int(f):
            return str(int(f))
    except (ValueError, TypeError):
        pass
```

随后长度校验失败，整行跳过：

```710:718:backend/routers/users.py
                if len(ehr_number) != 7 or not ehr_number.isdigit():
                    error_count += 1
                    error_msg = "EHR号格式错误（必须为7位数字）"
```

**资产导入侧**：同一原因，`使用人EHR号` 列读到 `1`，去 `users` 表匹配 `ehr_number = '1'` 查不到（库里存的是 `'0000001'`）：

```925:925:backend/routers/assets.py
        df = pd.read_excel(io.BytesIO(contents))
```

```1045:1053:backend/routers/assets.py
                        user_ehr = row_cell_str(row, df.columns, '使用人EHR号')
                        if user_ehr:
                            user = db.query(User).filter(User.ehr_number == user_ehr, User.deleted_at.is_(None)).first()
                            if user:
                                user_id = user.id
                                if not user_group:
                                    user_group = u.group
                            else:
                                raise ValueError(f"使用人EHR号{user_ehr}不存在")
```

资产导入命中使用人的优先级为：`所有人ID` > `所有人`（姓名）> `使用人EHR号`（`assets.py` 第 1022-1053 行），三条路径都受影响。

> 注意：数据库侧没有问题。`User.ehr_number` 是 `String(7)`（`backend/models.py` 第 48 行），`init_db.py` 创建的管理员账号 `0000001` 在库中是完整保存前导零的。问题**只发生在 Excel 读取阶段**。

### 修复方案

**方案 A（推荐，治本）**：读取 Excel 时强制按字符串解析

```python
# backend/routers/users.py 第 669 行
- df = pd.read_excel(io.BytesIO(contents))
+ df = pd.read_excel(io.BytesIO(contents), dtype={'EHR号': str})

# backend/routers/assets.py 第 925 行
- df = pd.read_excel(io.BytesIO(contents))
+ df = pd.read_excel(io.BytesIO(contents), dtype={'使用人EHR号': str, '资产编号': str})
```

若担心还有其他数值列（资产编号、卡片编号、显示器资产编号等）也被误转，**用户导入和资产导入都可以直接全局 `dtype=str`**，由 `cell_to_str` / `str_to_int` 各自按需转换。

**方案 B（兜底容错）**：校验前补零

```python
# backend/routers/users.py 第 710 行之前
if ehr_number.isdigit() and len(ehr_number) < 7:
    ehr_number = ehr_number.zfill(7)
```

```python
# backend/routers/assets.py 第 1046 行，取到 user_ehr 之后
if user_ehr.isdigit() and len(user_ehr) < 7:
    user_ehr = user_ehr.zfill(7)
```

> 建议 A + B 同时上：A 保证原始值不丢，B 兜底历史 Excel 模板（数值格式）仍然可用。

### 临时规避办法（不改代码也能用）

在 Excel 中把 `EHR号` / `使用人EHR号` 两列设为**文本格式**再填，或在单元格内容前加英文单引号 `'0000001`。
