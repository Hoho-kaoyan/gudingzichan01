## 2.1 实物名称→检查类型映射

- **代码**：`safety_check_linkage.get_check_type_for_asset` 使用 `asset.name.strip()` 查 `SafetyCheckAssetTypeMapping.asset_type`。
- **文档**：  
  - 《文档一致性与联动安全检查实现方案》4.2.1 已写「asset.name（实物名称）」与「asset_type = asset_name」，与代码一致。  
  - 《人员A工作完成情况与人员C工作解析》中仍保留「文档方案是按 category_id（资产大类）、实际实现是按实物名称」的**历史差异描述**，易造成误解；建议改为「文档与实现均已按实物名称」，或删除该差异表述。

## 2.2 逻辑删除与删除接口

- **资产**：`deleted_at`/`deleted_by_id`，删除接口只置这两项；查询统一 `deleted_at.is_(None)`。✅ 与《删除与导入逻辑优化方案》一致。
- **用户**：当前为 `db.delete(user)` 物理删除，无级联；《删除与导入逻辑优化方案》建议改为逻辑删除。
- **检查类型/任务**：停用/取消为状态字段，不删行。✅ 一致。

## 2.3 资产导入

- **当前**：必填列「资产编号、所属大类、实物名称」；存在且未删除则跳过；**存在且已删除时走新增会触发唯一约束报错**。
- **《删除与导入逻辑优化方案》**：建议存在且已删除时改为「恢复+更新」该行，不插入。  
- **《资产导入字段扩展方案》**：响应用户提出的导入字段调整需求，含新增字段列表（件数、所在团队、购置日期、卡片编号、电脑/显示器/联系人等）、列名兼容（实物状态/状态、存放楼层/具体存放楼层、终端IP号/IP地址等）、迁移与实施顺序。

## 2.4 外键与级联

- **代码**：无 `ForeignKey(..., ondelete="CASCADE")`；仅 `SafetyCheckTask → TaskAsset` 有 `cascade="all, delete-orphan"`，且任务不物理删。  
- **结论**：与《删除与导入逻辑优化方案》中「不推荐库级 CASCADE、推荐逻辑删除」一致。
