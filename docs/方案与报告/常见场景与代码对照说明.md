# 常见场景与现有代码对照说明

本文档对照「常见场景流程」与当前系统实现，说明**已支持**的场景及操作、**未实现或逻辑不一致**的差异，便于后续改造或产品约定。

---

## 一、场景一：资产入库

### 1.1 单个资产入库

| 场景描述 | 当前代码是否支持 | 具体用户操作 |
|----------|------------------|--------------|
| 管理员通过「新增资产」填写资产信息（编号、名称、位置等） | ✅ 支持 | 管理员登录 → 资产管理 → 新增资产 → 填写资产编号、所属大类、实物名称、存放地点等 |
| 直接分配给所有人则填写所有人；不分配则所有人默认为「仓库」 | ✅ 支持 | 使用人选择具体用户即分配；不选使用人则使用人为空（资产即视为在库）；系统另有 EHR 1000000 的「仓库」用户，退回审批通过后资产会挂到该用户下 |
| 入库且直接分配时，联动数据安全检查，所有人需对新资产进行安全检查 | ❌ 未实现 | 当前无「入库即自动发布检查任务」逻辑，检查任务仅能由管理员在「安全检查任务」里手动选择资产与检查类型后发布 |

**差异小结**：  
- 入库流程、分配/不分配（含仓库）与现有功能一致。  
- **差异**：场景要求「直接分配则联动安全检查」，当前需管理员事后手动发布检查任务。

---

### 1.2 批量资产入库

| 场景描述 | 当前代码是否支持 | 具体用户操作 |
|----------|------------------|--------------|
| 管理员用 Excel 记录资产信息，通过「批量入库」上传，系统解析并生成资产记录 | ✅ 支持 | 管理员 → 资产管理 → 批量导入 → 上传符合格式的 Excel（必填：资产编号、所属大类、实物名称；可选：使用人EHR号等） |
| 若入库资产直接分配给所有人，联动数据安全检查，所有人需对新资产进行安全检查 | ❌ 未实现 | 同上，无批量导入后按「分配」自动发布检查任务的逻辑 |

**差异小结**：  
- 批量入库、Excel 解析、分配使用人均已实现。  
- **差异**：缺少「批量分配 → 自动为该批资产发布安全检查任务」的联动。

## 二、场景二：正常资产交接（员工申请转移 / 管理员或组长调拨）

### 2.1 情况一：员工主动发起资产转移申请

| 场景描述 | 当前代码是否支持 | 具体用户操作 / 差异 |
|----------|------------------|----------------------|
| 员工 A 或管理员在系统发起该资产的交接申请 | ✅ 支持 | 员工 A 或管理员 → 资产交接 → 申请交接 → 选资产、选转入人、填原因 → 提交 |
| 若该资产需做数据安全检查且存在未完成检查任务，**不允许继续交接**，并提示「请先由当前所有人完成数据安全检查」 | ❌ 未实现 | 当前创建交接申请时**不校验**该资产是否有未完成的安全检查任务，可直接提交 |
| 当前所有人（员工 A）在「我的检查任务」完成检查并提交结果 | ✅ 支持 | 员工 A → 我的检查任务 → 选择任务 → 对资产逐项检查并提交结果 |
| 检查完成后继续交接申请流程，管理员审批通过后资产所有人变更为员工 B | ✅ 支持 | 转入人先在「资产交接」中确认/拒绝 → 管理员 → 审批管理 → 审批通过 → 资产使用人变更为 B；未完成的安全检查任务会**自动转给 B**（不会要求 A 先完成） |

**逻辑差异小结**：  
- **场景要求**：有未完成检查任务时**禁止**发起/继续交接，必须由当前所有人先完成检查。  
- **当前实现**：不拦截；审批通过后，该资产上未完成的检查任务会直接转给新所有人（B），原所有人（A）无需先完成。

---

### 2.2 情况二：管理员/组长调拨（直接改「所有人」）

| 场景描述 | 当前代码是否支持 | 具体用户操作 / 差异 |
|----------|------------------|----------------------|
| 管理员/组长通过修改资产信息中的「所有人」进行调拨 | ✅ 部分支持 | 管理员 → 资产管理 → 编辑资产 → 修改「使用人」并保存即可生效（无「组长」角色，仅管理员可改所有人） |
| 发起调拨后，系统**向原所有人（员工 A）发起**数据安全检查任务 | ❌ 未实现 | 当前修改使用人后，只会把该资产**已有**的未完成检查任务**改派给新所有人（B）**，不会对**原所有人 A** 新发检查任务 |
| 员工 A 完成安全检查后，调拨自动完成，员工 B 无需接收 | ❌ 不一致 | 当前「调拨」= 管理员直接改使用人，改完即生效，没有「等 A 完成检查后才生效」的步骤，也没有「B 无需接收」的单独逻辑（因为本身就没有转入人确认环节） |

**逻辑差异小结**：  
- **场景要求**：调拨 = 改所有人 → 给**原所有人 A** 发检查任务 → A 完成后调拨才生效，B 无需确认。  
- **当前实现**：调拨 = 管理员直接改使用人，立即生效；未完成任务转给 B，不给 A 发新任务，也无「完成检查后才生效」。

## 三、场景三：员工离职 / 退休 / 调离团队

| 场景描述 | 当前代码是否支持 | 具体用户操作 / 差异 |
|----------|------------------|----------------------|
| 管理员在系统标记员工为「离职」状态 | ❌ 未实现 | 用户表无「状态」字段（在职/离职等），无法标记离职 |
| 系统提示「是否完成数据安全检查进行资产交接？」→ 选择「是」 | ❌ 未实现 | 无此交互与流程 |
| 系统按预设模板为该员工名下资产自动发布数据安全检查任务，分配给该员工 | ❌ 未实现 | 无「按模板自动发布」、无「按用户名下资产批量生成任务」 |
| 该员工完成所有检查任务并提交结果 | ✅ 支持 | 员工 → 我的检查任务 → 完成并提交（若已有任务） |
| 检查完成后员工提交资产退回申请，管理员审批通过后资产变为「库存备用」，未完成检查任务标记为「已退库」；或不做退回、直接做交接 | ✅ 部分支持 | 退回：员工提交退回申请 → 管理员审批 → 通过后资产状态为「库存备用」、使用人可清空或改为仓库用户；审批通过时，该资产未完成的安全检查任务会被标记为「已退库」。交接流程也有。**缺失**的是：离职标记、自动发布检查任务、以及「先完成检查再允许退库/交接」的强制顺序 |

**逻辑差异小结**：  
- 场景依赖：**用户状态（离职）**、**标记离职时的确认与自动发布检查任务**、**先检查后允许退库/交接**。  
- 当前：无用户状态、无自动发布、无「未完成检查则不允许退库/交接」的拦截；仅「退回审批通过后任务标记已退库」与「交接/退回」两条流程本身存在。

## 四、场景四：长期出差 / 借调 / 产假等长期离岗

| 场景描述 | 当前代码是否支持 | 差异说明 |
|----------|------------------|----------|
| 管理员标记员工为「长期出差」「借调」「产假」等状态 | ❌ 未实现 | 用户无状态字段 |
| 系统提示「是否交接资产？」→ 选「是」或「否」；选「否」时再提示「是否变更数据安全检查执行人？」 | ❌ 未实现 | 无此类状态与弹窗流程 |
| 按预设模板发布检查任务；可选：任务仍给当前所有人，或变更执行人 | ❌ 未实现 | 任务当前仅能手动发布，且任务执行人固定为**资产使用人**，无「执行人」与「所有人」分离 |
| 用户状态变更为在岗时，安全检查执行人变更为资产所有人 | ❌ 未实现 | 无用户状态与执行人切换逻辑 |

**逻辑差异小结**：  
- 整条场景依赖：用户状态、离岗时是否交接/是否变更执行人、按模板发布、执行人与所有人分离、在岗后执行人回退为所有人。  
- 当前均未实现。

## 五、场景五：资产盘点

| 场景描述 | 当前代码是否支持 | 具体用户操作 / 差异 |
|----------|------------------|----------------------|
| 管理员在「数据安全检查」中设置盘点任务模板，通过「任务发布」发布资产盘点任务 | ✅ 部分支持 | 管理员 → 安全检查任务 → 检查类型管理（可新增「资产盘点」类）→ 发布新任务 → 选检查类型、选资产、填标题/描述/截止时间 → 提交；任务自动分配给资产使用人 |
| 系统将盘点任务分配给对应资产所有人，所有人登记盘点结果 | ✅ 支持 | 资产所有人 → 我的检查任务 → 选择任务 → 对资产逐项填写检查结果并提交 |
| 管理员可取消任务、修改任务（仅未进行的）、查看任务详情与进度、**导出任务结果** | ✅ 部分支持 | 取消任务、查看任务详情与进度已有；**修改未进行任务**需看前端是否暴露；**导出任务结果**在接口层未实现（无导出接口） |

**逻辑差异小结**：  
- 把「资产盘点」做成一种「检查类型」，用现有安全检查任务流程即可大部分满足。  
- **差异**：缺少「任务结果导出」接口与前端导出能力；任务编辑（仅限未进行）若有需求需在前端/接口上明确。

## 六、场景六：资产信息修改

| 场景描述 | 当前代码是否支持 | 具体用户操作 |
|----------|------------------|--------------|
| 所有人可对名下资产信息进行修改（资产编号、所有人不可修改） | ✅ 支持 | 普通用户 → 资产管理 → 编辑（仅自己名下）→ 修改除资产编号、使用人以外的字段 → 提交**编辑申请**，管理员审批通过后生效 |
| 管理员可对所有资产信息进行修改（资产编号不可修改） | ✅ 支持 | 管理员 → 资产管理 → 编辑 → 可直接修改除资产编号外的所有字段并保存，无需审批 |
| 不可修改的栏位系统会提示 | ✅ 支持 | 前端对普通用户会禁用资产编号、使用人等；管理员仅资产编号不可改 |

**小结**：与场景描述一致，无需改逻辑。

## 八、总表：场景与实现对照

| 场景 | 已实现部分 | 未实现或与场景不一致的部分 |
|------|------------|----------------------------|
| **场景一 资产入库** | 单个/批量入库、分配或不分配（含仓库） | 分配后自动联动发布安全检查任务 |
| **场景二 正常交接** | 员工/管理员发起交接、转入人确认、管理员审批、任务随资产转给新所有人 | ① 有未完成检查任务时**禁止**交接并提示先完成检查；② 调拨时向**原所有人**发检查任务且 A 完成后调拨才生效；③ 无「组长」角色 |
| **场景三 离职/退休/调离** | 退回/交接流程、审批通过后任务标记已退库 | 用户离职状态、标记离职时的确认、按模板自动发布检查任务、先完成检查才允许退库/交接 |

| **场景六 资产信息修改** | 与描述一致 | — |
| **场景七 用户管理** | 单个/批量用户、角色与组别维护 | 用户**状态**（在职/离职等） |

## 九、建议实现顺序（若按场景补齐）

1. **用户状态**：为用户表增加状态（如在职/离职/长期出差/借调/产假等），并做基础维护与展示，以支撑场景三、四。  
2. **交接前强制完成检查**：在创建交接申请（及可选：在转入人确认或审批前）校验该资产是否存在未完成的安全检查任务；若有，则拒绝并提示「请先由当前所有人完成数据安全检查」。  
3. **入库/批量导入后自动发布检查**：在「新增资产」与「批量导入」中，当资产分配了使用人时，按预设检查类型（或配置）自动为该资产创建安全检查任务并分配给该使用人。  
4. **离职流程**：标记用户为离职时，弹窗确认「是否完成数据安全检查进行资产交接？」；若选是，按模板为该用户名下资产自动创建检查任务并分配给该用户；在退库/交接前校验其名下资产是否均已完成检查（或至少本系统要求的检查）。  
5. **调拨流程**：管理员直接改「所有人」时，先向原所有人发布检查任务（或校验已有任务已完成），再允许保存；或保存后生成「原所有人待完成检查」任务，完成后调拨才生效（需明确产品规则）。  
6. **任务结果导出**：为安全检查任务（含盘点类）增加导出接口与前端导出，满足场景五。  
7. **场景四（长期离岗）**：在用户状态与执行人分离设计明确后再实现。

以上为常见场景与现有代码的对照及差异说明，可直接用于需求评审与开发排期。
