# 核心功能投产范围与确认事项

本文档记录需求变更后的核心功能范围、用户确认事项及本期投产与测试优先级。

---

## 一、用户确认事项（已确定）

| 序号 | 确认内容 | 结论 |
|------|----------|------|
| **1** | 资产批量导入是否包含「为带使用人的资产自动创建安全检查任务」 | **包括**。批量导入时，对成功入库且带使用人的资产自动创建安全检查任务。 |
| **2** | 管理员发布数据安全检查任务相关能力中，本期必须包含的范围 | **只包含联动配置页**，其他（如任务列表按来源筛选等）不包含在首版必须范围。 |
| **3** | 联动功能是否纳入本期 | **纳入本期**。入库/交接/调拨/离职联动、组长、用户状态与标记离职等均在本期范围内。 |
| **4** | 测试是否优先对齐核心功能 | **需要**。测试需优先对齐核心功能，详见 [核心功能测试优先清单](../测试/核心功能测试优先清单.md)。 |

## 二、本期投产核心功能定义

### 2.1 核心功能一：管理员发布数据安全检查任务（含联动配置）

- **必须包含**：
  - **联动配置页**（在「安全检查任务」页内以 Modal 形式）：全局默认检查类型、实物名称→检查类型映射的配置与保存。
  - 管理员发布任务流程：选择检查类型、选择资产、设置截止时间等，任务自动分配给资产使用人。
  - 普通用户在「我的检查任务」中执行检查并提交结果（yes/no）。
- **本期不强制**：任务列表按来源（manual/inbound/transfer 等）筛选等增强功能，可按资源情况后续迭代。

### 2.2 核心功能二：资产批量导入（含入库联动创建任务）

- **必须包含**：
  - 管理员通过 Excel 批量导入资产（格式校验、成功/失败反馈、错误明细）。
  - 对**成功入库且带使用人**的资产，系统按联动配置（默认检查类型或实物名称→检查类型映射）自动创建安全检查任务并分配给该使用人。
- **说明**：失败行不创建任务；联动创建任务失败不应导致整笔导入失败（当前实现为单行任务创建失败打日志，不影响其他行）。

## 三、联动功能本期范围

以下联动能力纳入本期，需与核心功能一并保证可测、可投产：

| 场景 | 说明 |
|------|------|
| **入库联动** | 单个新增资产、批量导入资产时，若使用人非空，按配置为该使用人创建安全检查任务（source=inbound）。 |
| **交接联动** | 创建交接申请时校验转出人是否有未完成检查任务；无则创建任务（source=transfer）；转入人确认、管理员审批前校验未完成检查则拒绝。 |
| **调拨联动** | 管理员/组长修改资产使用人时，不直接改使用人，而是创建任务（原所有人或新所有人），待生效调拨在任务完成后生效。 |
| **离职联动** | 用户状态与标记离职；标记离职时可批量为该用户名下资产创建检查任务；退库/交接提交前校验该用户是否仍有未完成任务。 |
| **组长角色** | 组长可对本组资产进行组内调拨，调拨逻辑与管理员一致（待生效调拨 + 任务完成后生效）。 |

实现方案与分工见 [文档一致性与联动安全检查实现方案](./文档一致性与联动安全检查实现方案.md)。

## 四、投产前稳定性要求

1. **核心功能及其相关功能代码平稳运行**：发布任务、联动配置、批量导入（含自动创建任务）、我的检查任务提交结果、交接/退回/审批、联动校验与任务创建等，无阻塞性错误与数据错乱。
2. **测试优先对齐核心功能**：执行测试时优先完成 [核心功能测试优先清单](../测试/核心功能测试优先清单.md) 中的用例，再扩展至联动与其它模块。
