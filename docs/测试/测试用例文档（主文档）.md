> 本文档为系统全功能测试用例主清单，覆盖三种角色（管理员 admin / 组长 leader / 普通用户 user）下所有功能模块。
> 用例编号规则：`TC-模块缩写-序号`；优先级：**P0（核心主链）/ P1（重要分支）/ P2（边界与异常）**。

## 1. 认证与登录模块（AUTH）

### TC-AUTH-001 EHR号回显（存在）【P0】
- 角色：任意
- 前置：账号 U01 已存在
- 步骤：登录页输入 EHR 号 `2000001`，移开焦点
- 预期：1 秒内回显"张三"，无报错

### TC-AUTH-002 EHR号回显（不存在）【P0】
- 角色：任意
- 步骤：输入 EHR 号 `9999999`
- 预期：显示"EHR号不存在"或 `exists=false`，不阻塞密码输入框

### TC-AUTH-003 EHR号格式校验【P1】
- 步骤：依次输入 `123456`（6 位）、`12345678`（8 位）、`123456a`（含字母）
- 预期：前端不允许提交/提示"必须是 7 位数字"；后端 `POST /api/auth/check-ehr` 同样校验

### TC-AUTH-004 正常登录【P0】
- 角色：A01 超管
- 步骤：输入 EHR `0000001` + 密码 `admin123`
- 预期：返回 token，前端跳首页，返回 `require_password_change=true`

### TC-AUTH-005 密码错误登录失败【P0】
- 步骤：EHR `0000001` + 错误密码
- 预期：返回 401，提示"EHR号或密码错误"

### TC-AUTH-006 离职用户登录拦截【P0】
- 角色：U05 钱七（status=离职）
- 步骤：用 U05 正确账号密码登录
- 预期：返回 401（authenticate_user 中 status=离职 即返回 None），无法登录

### TC-AUTH-007 已逻辑删除用户登录拦截【P1】
- 前置：管理员软删某用户
- 步骤：用被删用户的 EHR + 原密码登录
- 预期：401，get_user_by_ehr 已过滤 deleted_at

### TC-AUTH-008 Token 失效跳转【P1】
- 步骤：登录后清除 localStorage 中的 token，刷新任意受保护页面
- 预期：API 401，前端 PrivateRoute 自动跳登录页

### TC-AUTH-009 Token 自然过期【P2】
- 步骤：构造一个 exp 已过期的 JWT 调用任意接口
- 预期：401，"无法验证凭据"

### TC-AUTH-010 无 Token 访问受保护接口【P1】
- 步骤：不带 Authorization 头请求 `/api/users/me`
- 预期：401（OAuth2PasswordBearer 拦截）
