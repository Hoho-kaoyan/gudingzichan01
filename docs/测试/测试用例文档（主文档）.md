## 一、测试环境与约定

### 1.1 环境要求

| 项目 | 说明 |
|------|------|
| 后端服务 | 默认 `http://localhost:8000`（启动：`cd backend && uvicorn main:app --reload --port 8000`） |
| 前端服务 | 默认 `http://localhost:3000` 或 `http://localhost:5173`（启动：`cd frontend && npm run dev`） |
| 浏览器 | Chrome / Firefox / Edge 最新版 |
| 数据库 | 已执行 `python backend/init_db.py`，表结构及初始数据已就绪 |

### 1.2 初始数据（仅依赖 init_db）

| 类型 | 说明 |
|------|------|
| 管理员 | EHR：`0000001`，姓名：系统管理员，密码：`1234567`（以 init_db 输出为准） |
| 仓库用户 | EHR：`1000000`，姓名：仓库（不在用户管理列表展示，用于在库资产归属） |
| 组长 | EHR：`1234567`，姓名：测试组长1，组别：测试组，角色：组长，密码：`1234567` |
| 普通用户 | EHR：`1234568`，姓名：测试用户1，组别：测试组，角色：普通用户，密码：`1234567` |
| 资产大类 | 办公用品、电子设备配件、家具、其他（init_db 创建） |

**其余测试数据（用户、资产、申请、任务等）均由前述用例创建，不单独准备。**

### 1.3 前置条件约定

- **P0 主链**：编号为 TC-001～TC-0XX 的用例构成一条**必须按顺序执行**的主链。每个用例的**前置条件**为：**前述 P0 主链用例（至上一编号）均已成功**。
- **分支用例（P1/P2）**：各章节内非 P0 用例可在「主链执行至某点」后按章节或依赖执行，其前置条件写为：**TC-001～TC-0XX（或至某编号）已成功**或**前述本分支相关用例已成功**。
- 执行时若某用例失败，需先修复再继续；后续用例均假设前序已通过。

### 1.4 优先级与执行顺序示意

```
[TC-001 管理员登录] → [TC-002 首页] → [TC-003 用户列表] → [TC-004 新增用户] → [TC-005 资产列表] → [TC-006 新增资产] → [TC-007 提交交接] → [TC-008 转入人确认] → [TC-009 审批通过] → [TC-010 安全检查类型] → [TC-011 发布任务] → [TC-012 我的任务执行] → [TC-013 统计看板]
         │                    │                │                    │
         └── P1/P2 登录异常等   └── P1/P2 用户   └── P1/P2 资产分支   └── P1/P2 退回/编辑/历史/组长等
```
