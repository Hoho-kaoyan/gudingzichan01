# 资产导入字段扩展方案

## 一、目标

在现有资产模型与导入逻辑基础上，支持您提供的完整 Excel 列集，并兼容多种列名（如「状态」/「实物状态」、「IP地址」/「终端IP号」等）。

---

## 三、实现步骤

### 3.1 数据库与模型层（backend）

**1）Asset 表新增列（models.py）**

在 `Asset` 类中增加以下列（均为可空，便于存量数据与旧导入兼容）：

```python
# 扩展字段（导入与详情用）
quantity = Column(Integer, default=1, nullable=True, comment="件数")
team = Column(String(100), nullable=True, comment="所在团队")
purchase_date = Column(DateTime(timezone=True), nullable=True, comment="购置日期")  # 或 Date
card_number = Column(String(100), nullable=True, comment="卡片编号")
safety_check_executor_id = Column(Integer, ForeignKey("users.id"), nullable=True, comment="安全检查执行人ID，为空则用使用人")
computer_type = Column(String(100), nullable=True, comment="电脑类型")
computer_usage = Column(String(200), nullable=True, comment="电脑应用")
computer_name = Column(String(200), nullable=True, comment="计算机名")
monitor1_model = Column(String(200), nullable=True, comment="连接显示器1型号")
monitor1_asset_number = Column(String(100), nullable=True, comment="连接显示器1资产编号")
monitor1_serial = Column(String(100), nullable=True, comment="显示器1序列号")
monitor2_model = Column(String(200), nullable=True, comment="连接显示器2型号")
monitor2_asset_number = Column(String(100), nullable=True, comment="连接显示器2资产编号")
monitor2_serial = Column(String(100), nullable=True, comment="显示器2序列号")
asset_contact = Column(String(200), nullable=True, comment="资产管理联系人")
```

并增加关系（若需要在前端展示执行人姓名）：

```python
safety_check_executor = relationship("User", foreign_keys=[safety_check_executor_id])
```

**2）数据库迁移（SQLite）**

项目未使用 Alembic，可采用以下方式之一：

- **方式 A（推荐）**：在 `backend` 下新增脚本 `scripts/add_asset_columns.py`，用 `engine.execute("ALTER TABLE assets ADD COLUMN ...")` 逐列添加上述字段（若已存在则跳过），执行一次后再启动应用。
- **方式 B**：若表可重建（无重要生产数据），可删除 `assets.db` 后由 `Base.metadata.create_all(engine)` 按新模型建表。

迁移脚本示例（仅 ADD COLUMN，不删表）：

```python
# 伪代码
new_columns = [
    ("quantity", "INTEGER DEFAULT 1"),
    ("team", "VARCHAR(100)"),
    ("purchase_date", "DATETIME"),
    ("card_number", "VARCHAR(100)"),
    ("safety_check_executor_id", "INTEGER REFERENCES users(id)"),
    ("computer_type", "VARCHAR(100)"),
    ("computer_usage", "VARCHAR(200)"),
    ("computer_name", "VARCHAR(200)"),
    ("monitor1_model", "VARCHAR(200)"),
    ("monitor1_asset_number", "VARCHAR(100)"),
    ("monitor1_serial", "VARCHAR(100)"),
    ("monitor2_model", "VARCHAR(200)"),
    ("monitor2_asset_number", "VARCHAR(100)"),
    ("monitor2_serial", "VARCHAR(100)"),
    ("asset_contact", "VARCHAR(200)"),
]
for col_name, col_type in new_columns:
    try:
        db.execute(f"ALTER TABLE assets ADD COLUMN {col_name} {col_type}")
    except Exception:
        pass  # 已存在则跳过
```

### 3.2 Schema 层（schemas.py）

- **AssetBase / AssetCreate**：为上述新增字段增加对应 `Optional[...]` 或带默认值字段。
- **AssetUpdate**：为所有新增字段增加 `Optional[...] = None`，便于部分更新。
- **AssetResponse**：增加上述字段及可选 `safety_check_executor: Optional[UserResponse]`，便于前端展示「安全检查执行人」姓名。

---

### 3.3 导入逻辑（routers/assets.py 中 import_assets）

**1）列名兼容**

- 状态：优先读「实物状态」，若无则读「状态」。
- 存放楼层：优先读「具体存放楼层」，若无则读「存放楼层」。
- IP：优先读「终端IP号」，若无则读「IP地址」。
- MAC：优先读「终端mac地址」，若无则读「MAC地址」。
- 使用人：若存在「所有人ID」则优先用其解析 `user_id`（整数）；否则用「使用人EHR号」查用户得 `user_id`。

**2）必填列**

- 保持现有必填：`资产编号`、`所属大类`、`实物名称`。
- 其余新增字段均为可选，有则写入，无则置空。

**3）逐行解析与写入**

对每一行：

- 按上表「建议模型字段名」从 Excel 列读取（做 strip、空字符串转 None、日期列用 pandas 或 datetime 解析）。
- 件数：支持「件数」列，若为空则默认 1。
- 购置日期：解析为 date/datetime 再写入，格式建议支持 `YYYY-MM-DD` 或 Excel 日期序列。
- 安全检查执行人ID：若提供则写入 `safety_check_executor_id`；导入后若该资产触发联动任务，**创建任务时**：若 `asset.safety_check_executor_id` 非空则用其作为 `assigned_user_id`，否则沿用 `asset.user_id`（需在 `safety_check_linkage.create_system_allocated_task` 的调用处或内部按此逻辑传参）。

**4）联动任务派发人**

- 在 `create_system_allocated_task` 的**调用方**（如 assets 入库、调拨、交接等）传入「分配人」时：若资产有 `safety_check_executor_id` 则传该 ID，否则传 `user_id`。  
- 或：在 `create_system_allocated_task` 内部增加 `asset` 参数或 `assigned_user_id` 由调用方按上述规则计算后传入，两种方式二选一即可。

---

### 3.4 前端（可选）

- **列表/详情**：若需展示新增字段，在资产列表、详情接口返回中已通过 AssetResponse 包含新字段即可；前端表格/详情页增加对应列或展示项。
- **导入模板**：提供 Excel 模板下载时，表头包含上述全部需求列名，便于用户按规范填写。
- **导入说明**：在「批量导入」页说明支持两种列名（如「状态」与「实物状态」），以及「所有人ID」与「使用人EHR号」二选一等。

---

## 四、实施顺序建议

1. **backend/models.py**：为 Asset 增加新列与 relationship。
2. **数据库**：执行迁移脚本，为 `assets` 表 ADD COLUMN。
3. **backend/schemas.py**：AssetBase / AssetCreate / AssetUpdate / AssetResponse 增加新字段。
4. **backend/routers/assets.py**：  
   - 导入列名兼容（状态/楼层/IP/MAC/所有人ID）；  
   - 逐行解析并写入所有新字段；  
   - 若有「安全检查执行人ID」，在调用 `create_system_allocated_task` 时用其作为派发对象（否则用 `user_id`）。
5. **safety_check_linkage**（可选）：若希望逻辑集中，可在 `create_system_allocated_task` 内根据 asset 的 `safety_check_executor_id` 与 `user_id` 决定 `assigned_user_id`，调用方只传 asset 或 asset_id。
6. **前端**：按需增加展示与导入模板/说明。

---

## 五、风险与注意点

- **SQLite 与日期**：`purchase_date` 若用 `DateTime(timezone=True)`，SQLite 会按文本存储；若仅需日期，可用 `Date` 或统一存为 `YYYY-MM-DD` 字符串。
- **所有人 vs 所有人ID**：「所有人」为展示用，可由所有人ID 或 使用人EHR号 查 User 得到姓名，导入时不必单独存「所有人」列。
- **安全检查执行人**：与「所有人」可不同；仅当导入列提供「安全检查执行人ID」时落库并参与派单，否则行为与现有一致（使用人即执行人）。
- **向后兼容**：所有新列可空、默认不破坏现有导入 Excel；旧表通过 ALTER ADD COLUMN 即可，无需清空数据。

按上述方案实施后，即可在「不改动现有核心逻辑」的前提下，支持您列出的全部导入字段，并兼容多种列名与可选列。
